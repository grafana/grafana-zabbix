💥 Query responses now follow the [Grafana data plane contract](https://grafana.github.io/dataplane/contract/timeseries). Metrics and Item ID queries declare the `timeseries-multi` type (one series per frame), SLI/SLA, Service status and trigger-count queries declare `timeseries-wide`, and the series name is carried on the value field itself instead of only in the display name. Two consequences are user visible. First, **value fields are named after the series** (e.g. `srv01: CPU load`) instead of `Value`: legends, panel titles and field overrides that match on the displayed name are unaffected since the display name is unchanged, but transformations and overrides that reference the literal field name `Value` (Organize fields, Filter fields by name, and the column headers of Table panels and CSV exports) must be updated to the series name. Second, **responses are no longer collapsed into a single "wide" frame**: each series is returned as its own frame, as the contract requires for series that may not share a time index, so Time series, Stat, Gauge and Table panels keep working directly while panels that need a single frame (Bar chart, Pie chart, XY chart) now require a `Join by field` transformation on the time field, and Table panels show a frame selector instead of merged columns. Alert rules are not affected: alerting reads the labels (`host`, `item`, `item_key`), which are unchanged, and Grafana's server-side expressions already derived the series name from the frame name.
